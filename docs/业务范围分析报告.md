## 1. 项目概述

| 项目 | 内容 |
| --- | --- |
| 服务名 | travel-trip |
| 定位 | 家庭公路旅行规划微服务（Family Road Trip Planning Service） |
| 形态 | Spring Cloud 微服务（zy 微服务生态成员） |
| 当前状态 | 骨架阶段，**尚无业务领域模型、API、数据库 Schema** |

`travel-trip` 是 `com.zy` 微服务体系（基于 `zy-starter-parent` 及 zy-common 系列公共模块）中的一个独立业务服务，围绕「家庭自驾出游的行程规划」这一场景提供领域能力。

## 2. 技术架构现状

### 2.1 技术栈

- **语言/框架**：Java 21 + Spring Boot（zy-starter-parent 管理）
- **微服务治理**：Spring Cloud Alibaba + Nacos（服务注册发现 + 配置中心，`pi.home:8848`，namespace `dev`）
- **持久层**：MySQL 8+（库：`travel-trip-dev` / `travel-trip`）+ MyBatis（zy-common-mybatis）
- **缓存**：Redis（zy-common-redis，`pi.home:6379`）
- **接口文档**：Swagger UI / OpenAPI（zy-common-doc）
- **运维**：Actuator 健康检查（`/actuator/health`）

## 3. 业务定位

服务解决的核心问题：**一个家庭（多人、多天、多地点）计划并执行一次公路自驾旅行时，从「构思 → 规划 → 途中 → 回顾」全过程的数字化支撑。**

与通用 OTA（在线旅行社）产品的区别在于：

1. **以「行程」为中心**，而非以「交易」为中心——不负责机票/酒店/门票的售卖与订单履约；
2. **以「家庭」为协作单位**——行程由多人共同维护，存在成员角色与分工；
3. **以「自驾」为交通假设**——路线、驾驶时长、加油/充电、中途休整是一等公民。

## 4. 业务范围分析（领域规划建议）

### 4.1 核心域：行程规划（Trip Planning）

本服务的主干，建议包含：

- **行程**：一次完整的公路旅行聚合根，含名称、时间范围、目的地、状态（草稿/确认/进行中/已完成/已取消）；
- **日程**：按天拆解，每天含住宿地、途经点、游玩安排；
- **路线段**：两地点间的驾驶段，含里程、预计驾驶时长、途经道路；支持多段串联；
- **停靠点 / POI**：景点、餐厅、服务区、加油站/充电桩、观景台等兴趣点，可挂在行程或日程下。

### 4.2 支撑域：协作与成员

- **同行成员**：行程关联的家庭成员，含角色（发起人/管理员/成员）；
- **行程协作**：成员可编辑行程、评论、投票（如候选目的地/餐厅二选一）；
- **分享**：生成分享视图给未注册用户（只读）。

### 4.3 支撑域：行程执行（途中）

- **清单**：打包清单、出发前检查清单（可勾选）；
- **预算与花费**：按行程/类目（油费、过路费、住宿、餐饮、门票、购物）记录实际支出与预算对比；
- **加油/充电记录**：里程、金额、单价的留痕，便于核算；
- **备忘与提醒**：出发提醒、预订确认信息留存。

### 4.4 通用能力（技术性，非业务）

- 行程数据导入/导出（便于备份与迁移）；
- 行程模板（如「川西小环线 5 日」可被复制为新行程）。

### 4.5 明确不做的（边界）

以下能力**不属于**本服务，应由生态内其他服务或外部系统承担：

| 能力 | 归属 |
| --- | --- |
| 用户账号、登录、鉴权 | 统一用户/认证服务（zy 生态公共能力） |
| 酒店/门票/机票交易与订单 | 交易类服务（本服务只留存预订确认信息） |
| 地图渲染、导航、实时路况 | 地图服务（本服务只存储路线的关键数据） |
| 支付 | 支付服务 |
| 消息推送渠道 | 消息中心服务 |

## 6. 风险与待决事项

1. **业务范围未经需求评审**：本报告第 4 节为领域推断，落地前需与产品方确认 MVP 范围；
2. **领域模型未建**：无实体、无表结构，第一步应从「行程-日程-路线段」核心模型建模；
3. **依赖本地环境**：Nacos/MySQL/Redis 均指向 `pi.home` 内网环境，新成员需先搭建基础设施；
4. **快照依赖**：`zy-starter-parent:1.0.0-SNAPSHOT` 为本地仓库依赖，CI/CD 需注意其可用性；
5. **外部数据依赖**：POI、路线里程/时长若需真实数据，需确定地图服务供应商与调用方式（尚未决策）。

## 7. 建议的下一步

1. 确认 MVP 范围（建议：行程 CRUD + 日程编排 + 成员查看，先跑通最小闭环）；
2. 输出领域模型设计文档（实体、关系、状态机）；
3. 设计数据库 Schema 与 API 契约（OpenAPI first）；
4. 搭建业务代码分层骨架（controller / service / mapper / domain）。
