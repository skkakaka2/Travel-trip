## Step 0：业务范围确认（决策点）✅ 已完成 2026-09-22，结论见文末附录

| 项 | 内容 |
| --- | --- |
| 目标 | 由负责人确认 MVP 业务范围，形成《业务范围确认单》 |
| 输入 | 业务范围分析报告 v0.1 |
| 输出 | 确认后的范围基线（更新入本文档附录），冻结后续 step 的设计边界 |
| 决策人 | 项目负责人 |

**需决策的三件事：**

1. **核心域范围**（三选一）
   - A. 最小闭环：行程 + 日程，单人使用
   - B. 标准：行程 + 日程 + 同行成员（多只读成员）
   - C. 完整：行程 + 日程 + 成员协作 + 路线段/POI
2. **支撑域取舍**（多选）：打包清单 / 预算与花费 / 加油充电记录 / 行程分享
3. **路线数据来源**（二选一）：接入真实地图 API（依赖外部供应商决策）/ 手动录入里程与时长

**验收标准**：三个决策点均有明确结论并记录在案。

### 冻结后的 MVP 范围基线

**核心域**：行程、日程（含手动录入的里程/时长字段）、同行成员（只读查看为主）
**支撑域**：打包清单、预算与花费、加油/充电记录、行程分享
**范围外**：路线段/POI 独立建模、地图 API 接入、成员协作编辑/投票、酒店门票交易、账号鉴权（生态公共能力）
